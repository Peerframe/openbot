## 本次批准的约束与近期顺序

目标围绕工作重新组织，不是逐文件翻译旧 Server：Bot 是持久身份，Task 是用户的工作目标，Run 是一次执行尝试，Action 是一次具体的受控动作，Artifact 是可独立访问的成果。聊天与频道是交互入口，不拥有任务生命周期。这是职责定义，尚未定死 SQL 模型，也不要求增加服务数量。

Python 后端保持模块边界。Runtime 提议决策；控制层拥有权限、预算、审批与持久结果。成熟工作流组件负责恢复编排，动作回执与核对策略处理外部副作用和本地提交之间的不确定性。引擎重放、工具调用 ID 都不能证明外部写入恰好一次；进程、虚拟环境或容器本身也不等于完成安全隔离。

近期顺序调整为：**S3 恢复方案选型与 S4 隔离设计 → S2/S3 任务完整流程 → S2 其余接口与客户端 → S4 真实工作 → S5/S6/S7 整体验收**。保留旧阶段编号以关联已有证据，不再先翻译完 CRUD。固定 DBOS 与 Temporal 版本，验证杀进程、审批等待、取消、撤权、重复派发和未知外部结果，再选择唯一恢复负责人，不叠加多套独立重试引擎。首个实验与生产实现分离。

已有成果区分为产品不变量、候选实现、过渡设施。保留有效测试和修复；候选代码按行为验收；会话互认与局部后端模式需安排退出。允许为目标行为重新设计内部模型、数据库和 API，但保护原始数据和历史迁移。语言方向仅根据新的实际证据调整，不受沉没成本或竞品选型左右。

WorkBuddy 的 Temporal 实验 Worker 与 Codex 独立故障程序已完成本地验收。下一步验证公开 Task/审批/副作用/核对/产物完整流程、生产持久化及执行隔离；引擎选择仍受这些门槛约束。未发出的 TASK_015 模型设置工作不再作为下一任务；此前未提交的研究与依赖改动保留，不因本决定被视作已验收或已启用。

## 产品与最终架构

交付可自部署的数字同事：保留身份与工作，通过工具完成有界任务，接受监督，安全恢复中断，复用经过审核的方法。
保留一个主仓库：TypeScript/React Web 与薄 Electron 客户端；Python 业务与权限控制层、可独立验证的 Python Agent Runtime；
PostgreSQL 与文件存储；隔离的 Linux 浏览器、工作目录和受限命令环境。优先复用成熟执行后端；Rust 仅在确有宿主需求时引入。

Server 表示职责和权威边界，不表示必须永远使用 TypeScript。迁移期间现有 Server 保持权威，每项迁移职责只有一个选定写入方。
凭据、审批和任务最终提交不交给模型。旧 TypeScript 业务后端是过渡实现，不形成永久双后端。

## 整体完成标准

用户创建 Bot，上传表格，在测试业务网站核对记录，委派独立核查，批准具体外部修改，关闭再打开客户端，经历人为服务中断，
获得可使用的结果文件，并将一条纠正审核为可复用方法后用于新输入。另需证明换模型保留资产、撤权不可绕过、合成旧数据可升级和恢复。
区分确定性/本地证据与真实外部服务证据。

新增目录、翻译代码、通过模拟测试或删除旧文件都不单独代表完成。必需开发仍未完成时总目标保持进行中。
发布、生产变更和不可逆清理，应先准备具体可审阅结果，并按适用授权执行。
