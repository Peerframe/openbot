# 原生 Agent

[English](NATIVE_AGENT.md) · [简体中文](NATIVE_AGENT.zh-CN.md)

OpenBot 可以在 Server 中执行有界的“模型判断 → 调用工具 → 观察结果 → 继续判断”循环。
迭代复用已发布的 Vercel AI SDK；任务、频道成员权限、回复和审计仍以 PostgreSQL 为准。

## 使用

1. 打开“设置 → 模型与 API”，选择 Kimi、OpenAI、Anthropic、OpenRouter 等受支持的服务，输入支持工具调用的模型 ID 和 API Key，
   勾选“启用原生 Agent”，验证并保存。元数据验证通过不代表该模型一定支持生成接口或工具调用。
2. 创建电脑配置为 `none`（不使用电脑）的 Bot，将其加入频道，选中它并发送新任务，
   例如“阅读当前频道，总结还没完成的任务”。
3. 任务会从排队变为运行中，检查器显示模型步骤和工具观察结果；成功后出现 Bot 回复并完成任务，
   失败原因显示在 Run 中。
4. 任务详情会显示“由 Server 执行”和已记录的输入/输出 Token。Owner 可以停止排队或运行中的
   原生任务；失败或取消后，可明确点击“重新提交任务”创建新任务，从原指令重新开始，
   并非从模型检查点恢复。这一操作不开放 Worker 任务取消。

默认不开启推理，已有的加密模型配置同样保持关闭。开启后，新建的 `none` 任务（包括定时提交的任务）
会将任务内容和按需读取的当前频道上下文发送给所选模型，可能产生 API 费用。最近一次开启前的旧任务
不会补跑。修改设置时需重新输入密钥；关闭或替换配置会中止正在推理的任务。Server 需持续运行；
远程 Desktop 使用其连接的 Server。

需要公开检索或带来源的报告时，可以直接要求搜索，或提供公开 HTTPS 网址并要求生成 Markdown 报告。
Kimi 复用已保存模型密钥调用官方搜索；其他聊天模型可以使用 Server 的独立 `TAVILY_API_KEY`，
显式配置后优先使用 Tavily。Desktop 仅在应用启动环境中明确设置此变量时将它传给 Server。
没有检索服务时仍可读取已知公开网址，不需要逐网址授权；原有按编号读取工具仍接受最多三个显式网址。
例如“阅读 https://example.com，生成带引用的 report.md”。任务成功后，频道和 Run 检查器会显示
可下载的文件。网页属于不可信资料；下载内容是模型编写的文本，不作为 HTML 执行。

Desktop 使用系统“保存报告”对话框，请选择新的 `.md` 文件名；已有文件不会被覆盖。
原生桌面壳继续禁止通用浏览器下载。

原生循环会读取当前 Bot 的名称、职责和描述，作为有界上下文，并记录使用的档案版本。
档案内容不会赋予工具权限，也不能覆盖执行策略。

频道分工、附件格式和插件设置详见[alpha.4 核心升级](CORE_UPGRADE.zh-CN.md)。

## 工具与限制

| 边界 | 行为 |
| --- | --- |
| `read_channel_context` | 最多 12 条有界消息，只读当前任务频道，排除任务创建后的消息 |
| `list_channel_bots` / `delegate_task` | 查看同频道原生 Bot，并以接收方独立身份执行子任务；每棵树最多两层、四个后代，禁止循环 |
| `read_attachment` | 分页读取任务明确携带的文本/代码；图片/PDF 仅交给已启用的 OpenAI/Anthropic 适配器，模型本身也需支持 |
| `call_plugin` | 以当前 Bot 身份调用已授权、精确声明已审阅的 MCP 工具；逐次确认模式需用户本次批准 |
| `read_task_status` | 最多 8 条当前频道的任务标题和状态，排除当前任务创建后的任务 |
| `web_search` | 使用当前官方 Kimi 服务或明确配置的 Tavily 服务搜索公开资料；查询最多 1,000 字符，响应有界，不自动重试 |
| `fetch` | 模型可选择公开 HTTPS 来源，复用现有 DNS 固定读取器；页面、时间和文本上限同 `read_public_page` |
| `read_public_page` | 按编号读取任务明确给出的最多 3 个网址；限时 15 秒，输入最多 512 KiB，提取文本最多 6,000 UTF-8 字节 |
| `write_report` | 最多准备 2 个 Markdown 文件；正文最多 24 KiB，加上 Server 来源记录后最多 32 KiB |
| 权限 | 严格参数结构；Server 从已领取 Run 绑定频道和 Bot，复查成员关系与状态；允许选择公开 HTTPS 来源，拒绝文件路径与私网目标 |
| 迭代 | 最多 8 轮模型调用、16 次实际工具调用（其中联网最多 4 次），每轮最多输出 1,024 Token（Kimi 为 4,096）；已报告累计输入达到 64,000 或输出达到 5,120 Token 后不再调用下一轮 |
| 时间与输出 | 整棵协作任务树限时 300 秒（未接入协作的运行时为 90 秒），单次 HTTP 30 秒；模型响应最多 512 KiB，指令/普通工具投影最多 16 KiB；不可截断的搜索证据序列化后最多 128 KiB；最终回复最多 8,000 字符 |
| 并发 | 每个 Server 最多 6 棵根任务树；同 Bot 同频道依次执行，不同 Bot 和同级委派可以并行，数据库领取防止重复 |
| 网络 | 固定模型/检索官方接口，加上有界的公开 HTTPS GET 和已审阅的 MCP 服务调用；来源 DNS 结果必须全部是公网地址，连接固定到已检查 IP 并校验原始 TLS 主机名；不跟随重定向、不提供代理、不自动重试；关闭 OpenAI 响应存储 |
| 生命周期 | 回复、报告元数据、完成状态和审计一起提交；发布失败时清理已准备的报告文件；重启时将中断的运行中任务标为失败，不自动重试结果不明或失败的任务 |

进度仅记录动作与结果摘要，不记录内部思维链、密钥或上游原始错误。每步模型报告的输入/输出
Token 和模型标识会持久化；缺失或非法计数保持未知。用量面板仅汇总已加载频道/工作区样本中
已知的记录，不代表全历史、费用估算或账单。中断中的请求可能产生尚未返回的上游用量。
累计 Token 门槛阻止下一轮调用，无法撤销已发出的请求；即使缺少用量，字节、时间和步骤上限
仍生效。状态更新和停机仍依赖数据库可用。

停止操作先提交取消状态与审计，再中止活动请求；停止父任务也会取消仍在执行的后代，迟到的结果不能覆盖已取消任务。
密钥拒绝、限流、模型不可用、配置变化、权限撤销、无效工具目标、用量冲突、技能或记忆变更、工具失败和执行上限都有固定的操作提示，
不自动重试。参见[执行体验调研](research/agent-execution-experience.md)。

当前工具不开放未共享记忆、技能执行、Shell、任意本地文件路径、通用私网访问、电脑输入或审批决定。明确添加的任务附件和按 Bot 授权的 MCP 工具提供上文说明的有限扩展入口。
使用 Worker 电脑配置的任务沿用原有调度与审批路径；原生任务需要未提供的能力时，应说明限制。
Hermes/Pi/OpenClaw 委派、浏览器观察/操作工具及任意桌面控制仍需后续适配和权限、符合性验证。

## 验证证据

测试使用真实 SDK 和两个提供方适配器，以确定性 HTTP 响应验证工具结果确实进入下一轮模型请求，
覆盖范围/参数拒绝、执行上限、配置启用、取消和持久化。一次性 PostgreSQL 集成测试覆盖并发领取、
旧任务不补跑、Worker 排除、跨频道隔离、成员撤销、事务回滚、仅一条回复和重启中断处理。
界面测试覆盖明确勾选启用，以及不虚构 Node 的 Server 进度。来源测试覆盖私有/保留地址、混合 DNS、
连接 IP 固定、原始 TLS 主机名、重定向、压缩、大小与取消；报告测试覆盖事务发布、回滚、来源记录和鉴权下载。

测试不发送付费请求，不证明真实模型可用性、回答质量或实机桌面控制。
参见[调研记录](research/native-agent-loop.md)、[网页与报告调研](research/agent-research-artifacts.md)和[执行计划](EXECUTION_PLAN.zh-CN.md)。

## 经审阅的记忆闭环

任务中可以要求员工保留可复用经验。模型通过 `propose_memory` 最多准备一条候选经验，只有任务
成功完成后才进入待审队列，不会直接改动记忆。打开 **员工 → 记忆 → 候选经验**，刷新后查看
来源任务、完整标题和正文；可先修改内容，再批准或拒绝。

“允许模型使用”默认不勾选：批准只保存一条内部、不可迁移的 Owner 记忆。明确勾选后，此员工
后续任务才可以发送给所配置的模型。已有记忆也可在编辑器单独启用。迁移后的旧记忆默认关闭，
机密、受限和密钥引用禁止启用。每个员工最多保留 50 条待审经验；满额后须先审阅队列。

`read_employee_memory` 读取至多 8 条最近允许使用的记忆，正文每条 2,000 UTF-8 字节、总投影
10 KiB，并标明截断、ID、修订和已审核经验的来源任务。任务采用首次读取的快照；后续模型步骤
及最终提交会复核权限和修订，关闭、删除或修改后不能继续使用旧快照。已发送给上游的内容无法
撤回。审计只记录 ID/修订；待审经验不能被模型检索，审阅并发不会产生重复记忆，拒绝后移除候选
正文，批准后的正文归 Owner 记忆管理。

这是一条受 Hermes Agent 启发的实验性“候选经验 → 人工审阅 → 后续任务使用”路径。可执行
SKILL.md、语义/全文检索、后台整理、保留策略、跨会话用户建模和自主技能学习尚未实现。
参见[研究记录](research/agent-reviewed-knowledge.md)。

## OpenRouter 多模型入口

在模型设置选择 **OpenRouter**，填写其当前目录中的具体 `author/model` ID。验证只读取密钥和
模型端点元数据，不生成回复；拒绝管理/配置型密钥、不匹配的模型 ID，以及已启用 Agent 但没有
声明工具能力端点的模型。元数据验证不代表真实推理质量、账户余额或当前生成服务可用。

Server 通过固定版本 @openrouter/ai-sdk-provider 3.0.0 调用固定聊天接口，要求支持所用参数，
关闭自动提供商回退，并发送 data_collection=deny 路由要求。OpenRouter 会将任务内容转交所选
模型提供商；这项请求策略不是第三方数据保留的独立认证。原有循环、输出、停止、记忆和用量
限制继续生效，不开放网页插件、BYOK 注入、任意端点或自动模型选择。目前仍只保留一份 Server
默认模型配置，多配置档案与每员工单独选模型尚未实现。参见[研究与兼容性限制](research/openrouter-model-entry.md)。

## Kimi K3

桌面版“设置 → 模型与 API”可选择 Kimi（月之暗面国内接口），默认模型为 `kimi-k3`。填写 API Key 并启用原生 Agent，密钥加密保存在服务电脑上，重启后保留。验证只读取模型列表，不生成内容。K3 使用低推理强度，每步最多 4,096 输出 token（含推理），遵循当前整棵任务树 300 秒、最多八步的限制。仅启用后新建的无电脑 Bot 任务自动执行，不会重放旧的排队任务。安装版原生 Agent 现已接入公开搜索和来源读取，详见[Desktop 联网工具集成](research/desktop-public-web-tools.zh-CN.md)。任务进度记录工具开始、完成或失败，不记录查询和结果正文。
