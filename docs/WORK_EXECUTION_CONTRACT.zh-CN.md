# 工作执行目标契约

[English](WORK_EXECUTION_CONTRACT.md) · [简体中文](WORK_EXECUTION_CONTRACT.zh-CN.md)

状态：2026-09-23 设计契约，尚不是已实现 API 或数据库结构。这是[现行计划](ARCHITECTURE_MIGRATION_PLAN.zh-CN.md)的细化，不另设路线图。[持久执行实验](../experiments/durable-execution/README.zh-CN.md)仅证明其覆盖行为；生产引擎及集成仍待验收。

## 身份与归属

| 对象 | 含义与生命周期 | 权威 |
| --- | --- | --- |
| Bot | 持久身份、审核知识与配置 | 控制服务 |
| Task | 工作目标、范围、预算、监督和已验证结果；不随聊天、进程、模型变化而消失 | 控制服务 |
| Run | 任务的一次获准尝试，固定策略、配置和相关规则引用 | 控制服务准入，引擎调度执行段 |
| Runtime 执行段 | 有界策略调用，交回检查点、动作提议、等待或候选结果 | Runtime 提议，控制层验证 |
| Action | 稳定的逻辑外部动作、不可变意图及观察结果 | 控制层准入，执行器提供证据 |
| Artifact | 独立可寻址的内容、摘要、来源和访问范围 | 文件服务与控制登记 |

引擎重试、换进程不会自行创建新的 Run；明确改策略重试可在同一 Task 下创建新 Run。同一意图的 Action ID 跨传输重试与恢复保持稳定；用户明确重做某动作须建立新 Action 与授权。模型工具调用 ID 仅用于关联。关闭客户端或修改聊天布局不改变这些身份。旧 Run 迁移须保留来源，不能把每条旧消息虚构成 Task 或改写 SQL 历史。

## 唯一恢复负责人

选定的持久执行引擎负责调度、持久等待和执行段续跑。控制层准入并保存领域事实，不再有第二个循环独立重试同一执行段。Runtime 不得绕过控制层重试外部副作用；执行器传输重试必须符合该 Action 的明确策略。

不能把无限 Agent/工具循环塞进一个可重试 activity/step。执行段需提供足够的、经验证的恢复状态，避免重复计费与重复动作：输入/上下文引用、策略与格式版本、模型观察、已消费纠正、技能/记忆版本、动作引用和候选产物。确定检查点格式前，先审查并测试成熟 SDK 的真实续跑接口。

等待批准不应要求 Runtime 进程常驻。引擎执行段成功不等于 Task 成功；Task 可能仍在等待批准或结果核对。

## 准入、结果与不确定性

派发前保存不可变动作意图、范围权限、目标/内容摘要、需要时的批准记录、预算预留及尝试归属。批准只适用于该意图；输入、权限变化或过期时重新校验，不能把旧目标的批准用于新动作。

区分未派发、已准入、确认已应用、确认未应用和结果未知。保存意图不代表已经派发，也不代表没有派发。进程退出、超时、租约过期、取消请求或没有回执，都不能证明外部操作失败。结果未知时使用适配器支持的权威查询或可靠回执；无法证明则保持任务未解决，交由明确的人为核对。幂等键只有在目标服务实际保证其范围与有效期时才有效。

尝试租约需要递增隔离令牌与条件提交，不能只有过期时间。旧 Worker 不得提交终态或使用新预算；外部防旧写入也需要执行器/目标服务真正执行隔离令牌，不能声称能撤销已发送的 HTTP 请求。

准入与撤权须有明确的串行判定点。已准入/在途动作可能在停止后仍产生影响，须保留回执并如实呈现不确定性。取消是阻止新准入并请求中止，不是回滚。

模型/工具准入前预留共享 Task 预算，按核实用量结算；引擎重放复用已有预留及结果。不明计费继续占用预算等待核对，不能退款后供其他 Run 重复花费。Runtime、Worker、模型不能自行增发预算或覆盖已记用量。

## 完成与客户端状态

只有目标工作经验证、必要动作结果均已确定、产物真实存在且摘要与访问范围通过检查、最终发布连同领域版本/审计提交后，Task 才完成。模型总结只是提议。部分完成、失败、取消和外部结果未知必须分别呈现。

客户端使用版本化投影；重连能获取一致快照。事件有明确排序与恢复规则，重复或丢失不能生成另一份权威状态。Web、Desktop、无界面入口共用命令。界面说明工作阶段和需要用户做什么，不暴露无助于决策的引擎术语。

## 下一项完整流程验收

用户交办小型 CSV 校对任务。Bot 读取行、核对本地业务测试站点、准备具体更新与结果文件后等待批准。关闭客户端并杀掉 Runtime/控制工作进程；在 Runtime 不存在时保存批准，重新连接看到同一 Task。另一分支在此期间撤权，验证没有新动作获准。

获批分支在外部更新后、保存回执前杀进程，恢复后核对结果而不再次更新。通过公开 API 验证产物、共享预算、审计和终态。还须验证业务提交与引擎入队的间隙、共享预算并发、计费后回执丢失、文件与登记不一致。未知结果需要可验证的最终解决路径，不能永久挂起。选择引擎前再验证真实网络分区下旧 Worker 竞争与执行中升级代码。仅使用合成测试数据。

此流程先于大范围 API 翻译；后续仍需真实模型、浏览器、隔离环境、升级恢复、教学和贡献者验收。
