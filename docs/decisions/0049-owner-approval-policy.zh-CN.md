# ADR-0049：Owner 审批策略与精确只读例外

- 状态：接受限定的 C4 契约
- 日期：2026-10-01
- English: [English](0049-owner-approval-policy.md)

Python Server 保持唯一授权来源。复用 Work 的可信提案、持久化精确审批与执行守卫。
Owner 可对内置产品读取和公网读取（`product_read`、`public_web`）增加确认：`inherit`
保留适配器最低要求，`required` 增加审批。精确 Bot/目标例外只取消这层额外确认，不能
取消适配器强制审批、增加任务访问范围或权限、延长 Action、改变回执，也不能授权未知工具。

例外只支持内置频道/附件读取与精确网页读取；搜索没有精确目标，不能例外。目标为单一频道或
附件 UUID，或无凭据、查询与片段的规范 HTTPS URL。拒绝通配符、域名范围、前缀、路径、命令
和目标列表。保存时验证 Bot 与目标存在，运行时仍检查原任务与来源权限。最多64项，版本冲突拒绝。
**删除、安装、改权限永远禁止例外。** 命令、浏览器、插件与未知操作也不开放例外，保持现有
最低审批/权限。配置范围仅为上述两类 Work 操作；服务端响应列明受保护类别。直接 Owner 操作
继续要求现有认证与 Origin，不提供全局自动批准开关。

记录严格策略及适配器原始最低要求。提案在同一事务计算审批；准入及产品/网页执行前持有策略
共享行锁复查，策略写入用排他锁。收紧策略或撤销例外后，尚未得到精确批准的自动 Action 在
准入及执行前返回 `approval_policy_changed`，需重新提案。已有精确批准仍有效；放宽策略不会
修改已待审提案。历史回执与未知结果继续可核对，不重新执行。已发出的网页请求可能在策略
提交后结束，不声称能撤销远程请求；保留防重放标记。缺失/损坏的策略不回退到放行。

写入要求 Owner Cookie、精确 Origin、严格大小限制、预期版本与原子审计。迁移初始化 `inherit`，
保留历史审批。C2/C7/C4 是独立 main 分支，后合并的迁移必须重新基于 main 编号，不覆盖历史。
不修改界面/设计文件、不新增依赖、不复制上游代码。

已复用原有策略及 Work 研究，对照官方拒绝优先规则与 GitHub 版本、许可、测试和问题：Cedar
4.13.0（Apache-2.0，`324d3c09fc94ab91464ec340eb81e4b167deb6f5`）和 OPA1.21.1（Apache-2.0，
`2a109e54103370d2ef288782ef3cb4c8a37902b2`）。二者仍需 OpenBot 自身的任务/来源/租约绑定，
固定两类设置优先使用现有事务守卫。具体来源、比较与退出条件见英文正文。先写失败关闭测试，
再实现；必须验证禁止类别、未知/通配目标、强制审批不可降低，以及真实数据库/HTTP 的认证、
并发版本、审计回滚、准入/执行时撤销和损坏数据；Worker 未执行时不能冒充完整 Worker 验收。
