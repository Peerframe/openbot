# 研究：可选 Python Server 容器

- 状态：已验收，本地打包与生命周期检查通过
- 日期：2026-09-23
- 目标：用正式 Server 镜像启动 Python 执行包，在临时 PostgreSQL 上验证启动、工具循环、取消、重启和停止。
- 边界：Server 继续掌握权限、凭据和持久化；同容器中的 Python 子进程不构成独立沙箱。

复用已完成的 [Server 容器研究](server-node24-production-container.md)、
[Python 激活研究](python-runtime-activation.md) 和 SDK/模式校验器审查。
此次定向查询 GitHub 官方 Python 镜像问题、Docker 多阶段构建和 Python venv 文档。
完整候选比较、许可证、查询和摘要见[英文研究](python-server-container.md)。

选择官方 Python 3.12.13 slim-bookworm，源提交
`3362634339580d3232e65a66dd5a36c47ae7ff14`，镜像索引
`sha256:4766d8b510c428e595d74b9cc5bbb2fae8e26316fffb4adc89908d79aacd58a2`。
其索引同时包含 amd64 与 arm64。保留 Node 24.21.0 和 npm 10.9.9 的现有精确固定。
镜像源码 MIT、Python PSF、Debian 组件保留各自许可证；不复制上游源码。

新增 `runtime-python` 构建目标和显式 Compose 覆盖文件，默认目标仍保留现有路径。
在相同不可变 Python 基础镜像、相同最终绝对路径中构建虚拟环境；不复制主机 venv，
不单独复制 Python 可执行文件而遗漏动态库，不引入新打包框架。
精确锁定运行依赖，只安装二进制 wheel，缺失时构建失败；排除 pytest、开发工作区和私有协作记录。
开发锁保持不变，Server 启动只接受完整的开发或运行配置，拒绝缺包、混装、额外包和版本漂移。

沿用 UID 1000、只读根文件系统、持久文件卷、受限临时目录和 SIGTERM。
切回默认镜像只影响后续任务，不表示迁移或重放正在执行的任务。
验收必须包括真实 SDK 工具循环与取消、Owner 登录、迁移、持久数据重启、异常依赖在数据库变更前拒绝启动。
扩展现有双架构容器 CI；本地模拟和托管运行分别说明。不声明已部署、已发布、真实模型调用或崩溃恢复。


## 首轮集成证据

本地 ARM Mac 的 Docker Desktop（Linux arm64）中，两种正式镜像均已完成构建和生命周期验收：
27 项迁移、真实 Owner 登录/API、文件和模型配置重启保留、正常停止。
Python 镜像通过 18 项运行依赖校验及 pip check，实际执行 Unicode 工具循环和取消，未安装 pytest。
缺失解释器时在创建迁移记录前拒绝启动；没有真实模型调用。

首轮脚本发现内部网络不公开宿主端口，已改为容器内有 5 秒期限的真实 HTTP 探针，保持网络隔离。
默认镜像缺失密码的负向观察，以及原有两项归档/来源验证子进程测试，在并发构建时超时；
构建结束后均以原门槛复验通过，没有放宽产品或安全检查。完整检查复验结果见下方。


## 最终验收

WorkBuddy 在 macOS 完成 418 项 Python 测试（原有 369 项、新增依赖配置 49 项）。Codex 审查并独立
复验了新增 49 项，把静态导入检查的表述限定为其实际检查范围。完整 `npm run check` 通过：
Server 625 项通过、84 项因数据库环境跳过；Web 329 项；Desktop 359 项、1 项跳过；Node 51 项、
3 项跳过。容器合约 13 项、固定启动检查 6 项通过，未调整任何超时门槛。

默认 TypeScript 和可选 Python 镜像均通过本地 Linux arm64 生命周期验收；Python 镜像还通过
ARM 主机上的 Linux amd64 模拟验收，其临时 PostgreSQL 使用宿主架构。
两种 Python 构建均精确安装 18 项运行依赖，真实子进程通过 Unicode 工具反馈、用量和取消检查。
各生命周期验收均完成 27 项迁移、Owner 登录、文件/模型设置重启保留和零退出码停止；
缺失 Python 时在创建迁移记录前拒绝启动。

现有必需 CI 已加入两个镜像目标的原生 amd64/arm64 验收，但新托管任务尚未运行。
