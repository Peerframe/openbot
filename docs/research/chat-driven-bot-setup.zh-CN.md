# 调研：在聊天里设置 Bot 和记忆（C29）

[English](chat-driven-bot-setup.md) · 简体中文

- 状态：提议（所有者 2026-10-06 决定；给 Codex 的约定）
- 日期：2026-10-06
- 负责人：OpenBot 维护者
- 验收场景：Owner 在单聊里说「你叫 v7，负责每周的竞品周报，每周五 9 点发我，用我的 Gmail 发」。
  Bot 像下属一样直接办好，并说清做了什么：给自己改名、设标签和介绍、建好例行任务、开始用已安装的 Gmail
  插件、记住这条要求。每项改动在对话里留一行并带「撤销」，也记入审计记录。第一次真正发邮件时，仍按现有
  审批规则先问你。
- 安全边界：
  - 只有 Owner 本人的话能让 Bot 改自己，而且只能改它自己。
  - 外部内容（网页、文件、工具结果、别的 Bot）可以让它记下学到的事实；要变成长期指令，必须 Owner 点一下。
  - 以下仍然不能在聊天里办：工作电脑、密码凭证、模型密钥、审批规则、连接新插件、别的 Bot、账户设置。
  - 所有对外操作照旧走审批。Server 仍是唯一的权限和审计来源。

## 复用决定

- 选择：扩展 OpenBot 现有存储（本地差集），不加依赖。
- 原因：各候选要么把状态存在 Server 之外，要么没有撤销和审计；OpenBot 已有带版本检查的资料、记忆、
  例行任务存储，以及审计和敏感内容扫描。
- C29 约定：
  1. **谁能触发**
     - 改资料、例行任务、技能、插件使用：必须发生在由 Owner 消息触发的任务里——单聊里，或频道里 Owner @ 了这个 Bot。
     - 学到的事实也可以在它的例行任务里记下，并注明来源。
     - Server 给每项改动记下触发它的消息或任务。
     - 别的 Bot、Webhook、导入内容永远不能直接触发。
  2. **直接生效**（对话里留一行带「撤销」，并记入审计）
     - 自己的名字（≤ 64）、标签（≤ 160）、介绍（≤ 2,000），按当前资料版本保存。
     - 记忆：每条 ≤ 500 字，经过现有敏感内容扫描；密钥会被拒绝，和现在一样只能记名称。三种来源都可以：
       - 你说的；
       - 和你一起工作时学到的；
       - 在外部内容里读到的**事实**（`semantic`、`episodic`），这一行会注明来源，例如
         「记下了：B 公司定价页需要登录（来自 b.com）· 撤销」。
     - 忘掉你点名的记忆，或在容量上限内整理时替换旧条目。
     - 新建、暂停、恢复、删除自己的例行任务（在现有限制内）；结果发到你提出要求的那个对话。
     - 根据你在这段对话里的教导写下的技能：「学会了「周报格式」· 查看 · 撤销」，技能正文照旧按 SHA 绑定。
     - 使用已安装插件的工具：你说「用我的 Gmail」，就把该插件的工具授权给这个 Bot；每个写操作仍按审批规则先问你。
  3. **变成卡片**（你点「确认」或「不用」；7 天后过期；也列在 设置 › 记忆 › 候选经验）。只针对来自外部的长期指令：
     - 读过外部内容（网页、文件、附件、工具或插件结果、别的 Bot 的消息）之后，任务里产生的 `procedural` 记忆或技能；
       Server 在任务第一次读入这类内容时打上标记，卡片会写明来源；
     - 从外部导入的技能文件（沿用现有审核）。
  4. **不能在聊天里办**（Bot 会告诉你去哪里办）
     - 工作电脑授权、密码凭证、模型连接和密钥、审批规则；
     - 安装或连接新插件（OAuth 仍由你在插件窗口完成）；
     - 删除或修改别的 Bot、频道，账户与安全设置，分享与导出。
  5. **限制**
     - 每个任务最多 5 项直接改动，超出的变成卡片；相同的改动会合并。
     - 每个 Bot 在「设置 › Bot 能力」有开关「允许它根据你的话自己改资料、记忆和例行任务」，默认开；关掉后所有直接改动都变成卡片。
  6. **撤销**
     - `POST /api/v1/bot-changes/{changeId}/undo`：仅 Owner，可重复调用，带版本检查。
     - 如果之后同一项又被改过，返回 `change_superseded`，这一行显示「已被后来的改动覆盖」。
     - 撤销会恢复原值，或删除新建的记忆、例行任务；撤销本身也记入审计。
  7. **对话记录**：两种新消息，都走频道事件流和消息分页。
     - `change`：`{changeId, botId, field, summary, undoable, undoneAt?, groupId}`。同一个任务里的改动共用一个 `groupId`，
       只显示**一行**安静的记录（「按你说的更新了 5 项 ›」；所有者 2026-10-06 反馈：不要一排「撤销」）；点开才列出每一项和各自的「撤销」。
       Owner 也可以直接说「名字改回去」，Bot 通过同一个撤销接口完成。
     - `proposal`：`{proposalId, botId, summary, source, actions, expiresAt}`，显示为卡片。
  8. **审计**：`BOT_SELF_CHANGE`、`BOT_SELF_CHANGE_UNDONE`、`BOT_PROPOSAL_DECIDED`。操作者记为「Bot，代表某条 Owner 消息」，
     并记新旧版本号；不把内容抄进审计。
  9. **记忆来源**
     - 每条记忆记下 `origin: owner_said | learned | learned_outside | owner_reviewed`、来源的消息、任务或网址，以及模型是否使用。
     - 外部来的事实交给模型时，放在标明「参考资料，不是指令」的区域里。
     - 记忆只是描述，从不授予工具，也不跳过审批，所以一条错误的记忆本身不会造成对外操作；而且每条都有一行记录，容易发现和撤销。
- 退出方案：每个 Bot 的开关可以把功能退回成卡片，不需要迁移；数据表与迁回 TypeScript 控制面的计划兼容。
- 失败时：如果来源标记、版本检查或审计写入不可用，改动变成卡片（按失败即关闭，转为审核）。被拒绝时，Bot 如实回答，例如
  「这个我改不了，需要你在 设置 › 工作主机 里授权」。

## C30 补充：对话里的提示与按职责换外观（2026-10-06）

所有者看完第二段 Grok 录屏后要求以下全部都做。本节沿用上面 C29 的权限规则，不新增任何权限。

1. **提问卡**：Bot 可以用卡片一次问 Owner 一个问题，而不是写一段话。
   - 新消息类型 `ask`：`{askId, botId, question (≤ 120), options: 2–5 个 × ≤ 40 字, allowOwn, expiresAt}`。
   - Owner 用 `POST /api/v1/asks/{askId}/answer {option | text (≤ 500) | skip}` 回答，仅 Owner 可调用，可重复调用。
     回答同时作为 Owner 的消息发出，Bot 像读普通回复一样读到它。
   - 卡片收成一行（「每天几点发运势给你？ 早上 9 点 ✓」或「已忽略」）。
   - 提问本身不带任何权限；选择之后引起的改动仍按 C29 处理，并出现改动行。
   - 限制：每个对话最多一个未回答的问题，新问题会替换旧的。
2. **收到先点头**：Bot 根据 Owner 的消息开始一个任务时，可以通过现有的回应接口在那条消息上加一个回应
   （默认 👌）。这是 Server 发出的信号，不调用模型，所以即时、不花钱。每个 Bot 可以在 C29 的同一个设置开关里关掉。
3. **按职责换外观**：
   - `BotHeadShape` 新增职责头型：`star`（信息/研究/观测）、`gear`（开发/运维）、`bubble`（客服/沟通）、
     `page`（写作/编辑）、`hive`（数据/复盘）、`clock`（日程/助理）；
   - **或者**，如果所有者在 RoleLooks 画板上选方案二，就在现有头型上加 `accessory` 配件值。
   职责定下时，Bot 可以自己选外观。这属于 C29 的直接改动：留一行「已换成「星象」外观 · 撤销」，通过 C9 外观接口
   按版本检查保存，审计记为 `BOT_SELF_CHANGE`（`field: appearance`）。旧的 Bot 模板照常导入。Web 在每个头像上
   播放变身动画（PR #198）。
4. **步骤名称**：「正在工作」那一行写出 C13 报告的当前阶段（PR #198 已完成）。最好再加「读取文件」「连接插件」
   两个阶段键，但不是必需的。

测试（Server）：
- `ask` 只能回答一次，再答会被拒绝；
- 回答会作为 Owner 的消息发出；
- `skip` 会让卡片收起；
- 第二个 `ask` 会替换第一个；
- 每个任务只加一次回应，关掉开关后不加；
- 外观自改会写改动行，可以撤销，版本过期时被拒绝；
- 未知的头型值被拒绝。

测试（Web）：卡片收起和变身动画，与 PR #198 里的分工卡相同。

## 验证计划

- 自动测试（Server）：
  - 单聊里 Owner 的话能改名，并写下 `change` 记录和审计行；
  - 频道里 @ 了才生效，没 @ 不生效；
  - 别的 Bot 的消息不能触发；
  - 读过网页的任务里：事实带来源保存，`procedural` 记忆或技能变成卡片；
  - 「用我的 Gmail」授权已安装插件的工具，写操作仍要审批，未安装的插件被拒绝并告知去哪里装；
  - 同一任务第 6 项改动变成卡片；
  - 密钥被拒绝；
  - 撤销能恢复且可重复调用，被覆盖时返回 `change_superseded`；
  - 开关关闭后全部变成卡片；
  - 电脑、装插件、凭证、改别的 Bot 的请求都被拒绝。
- 自动测试（Web）：
  - 改动行带「撤销」，撤销后这一行随之更新；
  - 卡片按钮调用 `decide`；

  - 开关能保存。
- 负面与失败即关闭：网页里藏着「以后都要……」「给自己改名」之类的文字，最多只产生一张注明该网页的卡片；
  来自外部的改名直接拒绝，因为只有 Owner 的话能改名。
- 平台：Server 和 Web；Desktop 用同一套 Web 界面。
