## Reuse decision

- Selected option: thin adapter over the existing HTTP standard, React and Zod.
- Exact gap: reachable shared task screen; create/read/cancel requests; ordered snapshot updates; same-request creation retry after lost acknowledgement; visible stale/unknown states.
- Replace the local projection adapter with a generated client when a repository generator exists. Pin this review to the server models above and test against the actual public OpenAPI/HTTP fixture before handoff.
- Missing/incompatible API or invalid snapshot fails visibly without a legacy API fallback or success state. A 401 uses the existing session invalidation event.
- No task listing route exists: offer explicit Task ID lookup. This first vertical slice defers approve/deny, reconciliation submission and work artifact saving; show their server facts without inactive imitation controls. Cancel delivery has no public acknowledgement field, so never infer delivery from persistence or completion from cancellation request.

```sh
npm ci
npm run build -- --filter=@openbot/web --filter=@openbot/db
sh apps/server-python/scripts/bootstrap.sh
apps/server-python/.venv/bin/python apps/web/src/test/work-http-probe.py
```

The probe creates a uniquely named loopback-only PostgreSQL container with tmpfs data, runs the
repository migrator, starts the real Python app with built Web assets, exercises the public API,
and removes only its own processes/container. Docker and the locked control Python environment
are required; it does not need a paid model account or maintainer-private credentials. Add
`--serve` to print an ephemeral `#/tasks` URL and disposable Owner password for interactive browser
verification; Ctrl+C cleans up the fixture. Open the displayed URL, log in, create an objective,
copy the Task ID, refresh/read, cancel, and reload/read the copied ID. Automated browser fault
injection is not part of this fixture; the recorded stop/restart interaction above was manual
agent-controlled verification.
