# 研究：MCP 兼容性预检与独立作者检查

- 状态：已采纳
- 日期：2026-09-22
- 负责人：OpenBot maintainers
- 关联工作：贡献者成长主线 P
- 验收旅程：生成独立插件后，不运行 OpenBot、数据库或模型即可验证成功和失败场景；Server 在安装前用同一工具规则拒绝不兼容声明。
- 权限边界：声明、响应和工具结果都不可信。预检只初始化并发现工具，不执行工具，也不授予权限。地址/DNS 限制、安装、授权、审批和审计仍由 Server 管理。

## 研究与复用决定

完整查询、版本与候选比较见[英文研究](mcp-compatibility-preflight.md)。本次重新检查 MCP
2025-11-25 生命周期、Streamable HTTP 和工具规范，以及 TypeScript SDK 1.30.0 的发布、
客户端/传输源码、测试、MIT 许可和通知确认相关 issue 2730。复用清单中的第三方 MCP、
生命周期与独立脚手架研究也已复核。

继续固定 `@modelcontextprotocol/sdk` 1.30.0，提交
`2d889f2b329e46680ec9bdd565de4616c497825a`，不增加依赖或迁移到拆包后的 SDK 2。
标准负责协议；SDK 负责协商、消息解析与输出 schema 校验；OpenBot 只补自身边界的薄适配。
MCP conformance `74edef34d674f563537be8c6587cebaa58e830ca` 的具名场景方式可借鉴，
其全协议检查不能替代本项目更窄的工具规则和 Owner 权限检查。

真实缺口是：SDK 已记录工具的 `execution.taskSupport` 并拒绝普通调用 required-task 工具，
但此前 OpenBot 在发现后丢弃该字段，仍允许安装这类无法执行的工具。
同时连接失败大多折叠成通用 unavailable，独立作者缺少无需整个产品的可运行负向检查。
已有 schema 子集和结果限制应抽出复用，而不是再写一套 schema 引擎。

## 实施范围与失败行为

共享无 workspace 导入的工具/schema/结果规则，发现阶段拒绝 required-task 工具；返回固定
`compatibility` 原因，区分认证、访问拒绝、传输、版本、schema、执行、目录、结果和超时。
错误不回显远端正文、认证挑战或 token。新安装/更新失败不产生权限；已有授权调用前仍复核声明。

独立作者命令只接受精确字面量回环 HTTP(S) 地址，限制响应大小和时间，禁止跳转。
它只检查声明，不执行工具，也不声称验证工具效果、资源/提示词、Server 地址授权或安装授权。
结果策略通过明确的本地测试数据验证，真实工具结果仍在授权调用后检查。

没有复制上游实现。生成项目复制现有 MIT OpenBot 示例、共享规则和测试，并保留仓库 LICENSE。
生成规则是版本快照，采用新规则时需要生成到新目录比较更新。

## 验证与限制

验收包括独立依赖安装、真实本地 SDK 示例、schema/task/认证/协议/超时等失败场景、
Server 预览和安装不产生授权、已有授权遇到不兼容声明时不发出工具调用，以及完整 `npm run check`。
本轮仅提供本地 Node/macOS 与仓库自动测试证据，不新增 Windows 或安全认证声明。
OAuth、task 执行、更多 schema 方言和完整 MCP conformance 留给独立后续主线。

## Owner 错误提示与验证结果

Web 插件适配器此前丢弃错误 JSON。本次只接受固定 `compatibility` 白名单并映射本地中文提示，
不显示远端 error、token、认证地址或其他字段。未知原因、原型属性名和非 JSON 响应继续采用
原有 HTTP 状态提示；16 项针对回归与 Web TypeScript 检查通过。

Server 针对回归 5 个文件、77 项全部通过；完整 `npm run check` 通过。独立目录自行安装依赖后，
最终 13 个作者场景全部通过；实际启动示例并运行 CLI 返回 MCP 2025-11-25、2 个工具与 0 次工具调用。
Server 完整套件有 69 项既有环境/平台依赖跳过，不能据此宣称这些环境已经验证。
