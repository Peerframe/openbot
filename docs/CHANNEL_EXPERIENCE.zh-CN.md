# Desktop alpha.5 频道体验

本轮在实际查看已安装的 Grok Bot 0.47.0 后重做频道。动代码前已说明消息布局、输入框、回复操作、协作状态、附件与对话连续性六项改动。OpenBot 保留自己的头像、导航和权限体系。

## 各部件的变化

| 部件 | 实际行为 |
| --- | --- |
| 消息记录 | Bot 灰色气泡、用户黑色气泡；同作者连续消息合并身份，头像位于最后一条气泡底部；间隔超过五分钟显示时间分隔。频道工具栏为 44px。 |
| 输入框 | 最小高度 44px，随文本增长；附件与发送按钮位于两端。多个接收者标签可同时保留，也可以不指定 Bot 直接发到频道。 |
| 接收者 | 一条消息最多指定六名不同的频道 Bot；Server 同事务校验全部成员，保存一条原消息并为每名接收者创建任务。“所有人”展开为当前精确成员 ID，超过六名会明确拒绝，不会悄悄省略。 |
| 回复 | 回复当前频道 Bot 时自动选中它；点击引用可定位原消息。模型首次调用前会收到有界的引用上下文，包含超出最近消息窗口的旧引用。 |
| 消息操作 | 所有窗口宽度下均默认隐藏回复、复制和任务详情；鼠标悬停或消息获得焦点时显示，触屏可点击气泡获得焦点。 |
| 工作状态 | 真实运行、排队、失败和取消状态进入对话流，后续任务显示等待接续。后来已有完成任务时，旧失败和取消记录只保留在对应消息详情中。Bot 委派保留发起者、接收者和可查看的任务关系。 |
| 附件 | 文件选择、拖放和粘贴截图/文件复用同一条受控上传路径。草稿和已发消息显示文件卡片；PNG/JPEG 可以放大，Escape 关闭。消息正文不再直接显示内部附件标记。 |
| 连续对话 | 排队任务开始前能读取前序任务刚完成的回复；后续独立人类请求不会混入当前输入。Server 在模型首次调用前提供上下文。 |

## 仍需明确的边界

- Bot 工作期间发来的新消息仍是独立排队任务。尚未实现即时改写正在执行的任务、逐字流式回答或任意异步 Bot 消息。现有委派上限和取消规则继续生效。
- 不指定接收者时复用 Server 的协调者/首成员路由，并非所有 Bot 自行投票选人。
- 本轮频道视觉调整没有新增语音输入、表情回应、移除成员或定时任务能力。产品已有工具和审批仍通过真实入口提供。
- 附件保留当前格式与大小限制：单任务八个文件、合计 20MiB。已发附件卡片不冒充新增的原文件原生下载能力；生成产出的下载入口保留。
- OpenBot 自有头像及周边导航是明确保留项。视觉验收按实际窗口尺寸、测量和剩余差异陈述，不宣称整个应用在所有状态下逐像素相同。

## 2026-09-10 界面验收

- 使用生产频道组件与合成数据，检查 1040×760 桌面及 390px 窄屏布局。标题栏、空输入框实测均为 44px，没有横向溢出；两种宽度下默认可见消息操作栏均为 0。
- 浏览器实际操作：同时选择两个 Bot 并发送一条消息，生成两个任务；回复 Nova 后核对收件人标签；点击引用并确认原消息获得焦点；打开 PNG 预览，Escape 关闭后焦点回到预览按钮；取消排队任务并观察状态更新。浏览器错误和警告日志为空。
- 文件选择、拖放、粘贴、部分上传失败和权限由组件及 Server 测试覆盖。界面中的图片预览使用预置合成附件记录，不冒充已经手动走通原生文件选择器上传流程。
- 安装后的原生应用另外检查真实工具栏、频道导航和保留的本地数据。参考服务的付费模型执行、实时异步委派仍未实测。
