## 重现只读检查

本地已有两条源码历史时运行：

```sh
npm run migration:compare -- --source-repo /path/to/feature-checkout --source-ref 9cc73c9e78451e572f57d142d6b9caf62ccb78e2 --target-repo . --target-ref c33e03f1a14de739196113769c59fdaace9029e7
```

程序只读取固定迁移目录内已提交的 Git 树/对象，忽略暂存或未提交文件，拒绝符号链接、无效清单和非提交引用。
不拉取源码、不连接数据库、不执行 SQL、不输出 SQL 正文。退出 0 仅表示相同历史或源历史是目标前缀；
1 表示分歧或反向升级；2 表示输入或读取错误。即使为 0，也不证明用户数据和文件兼容。
当前两条基线应返回 1。`npm run migrations:check` 运行对应本地夹具。

## 保留范围与后续兼容方案

迁移分支的 0000–0026 历史保持不变。功能分支中要保留的行为通过目标分支的后续变更接入。
这不代表旧分支数据库自动兼容：S7 必须使用两条历史各自生成的临时合成数据库，验证经过调研的转换/迁移方案，记录来源历史和行/文件来源。
S2 固定目标模式与模型配置职责后再决定具体方案；当前尚未实现数据转换程序。

保留 Bot/频道/消息 ID、任务结果与祖先关系、审核技能和记忆、日程、审批/审计、附件和对象，以及每条分支的模型配置。
模型密文不能直接复制：功能分支将连接记录存在 PostgreSQL 并使用独立密钥文件；迁移基线的加密模型设置在数据库外。
凭据继续单独保护，不进入源码报告或模型提示。保留浏览器会话绑定；登录状态不随普通模板导出。

最终转换须停止竞争写入，验证关联、数量、摘要和权限，生成可以恢复的数据库与文件配套备份，并明确切换后产生新数据时如何回退。
只保留旧代码或旧数据库快照，不足以构成切换后的安全回退方案。外部写入结果未知时先核对。本文件不授权生产变更。
