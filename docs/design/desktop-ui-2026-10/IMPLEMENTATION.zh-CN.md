# Desktop 界面实施计划

[English](IMPLEMENTATION.md) · [简体中文](IMPLEMENTATION.zh-CN.md)

## 一分钟看懂

- **要做什么：** 让 Desktop 和 Web 应用和所有者画布上的设计（[画板](README.zh-CN.md)）一模一样。规则在
  [DESIGN.zh-CN.md](DESIGN.zh-CN.md)；画布优先于任何旧界面或旧文案。
- **谁做什么：** Claude 负责你能看到、能点到的一切（界面、布局、动效、文案、键盘操作）；Codex 负责背后的
  部分（服务电脑、数据、Desktop 主进程、CI）。两边通过写清楚的约定衔接，也就是下面的待办 C1–C24。
- **你怎么检查：** 每一步是一个拉取请求，里面有实现界面和画板的并排截图。你看图、按列出的步骤点一遍，
  不需要读代码。
- **你要决定的：** 本文末尾的待定问题，以及第 22 步的新设计（先确认再实现）。

## 分工

每个文件范围只有一个实现者（根目录 `AGENTS.md`）。跨范围的需求走待办。

| 负责方 | 范围 |
| --- | --- |
| Claude | 界面与体验：`apps/web/src/**`（组件、样式、Web API 客户端 `api.ts`）、界面测试、设计预览工具、`docs/design/**`、画布 |
| Codex | 后端与平台：`apps/server-python/**`、`packages/db/**`、`packages/protocol/**`、`packages/domain/**`、`apps/desktop/src/**`（主进程与预加载）、桌面打包与图标、CI 与脚本 |

后端事项要等它的接口或桥接方法、领域与协议类型、测试都已合并并写进 `docs/API.md`，界面才能接入。在那
之前，需要它的设计元素先隐藏，绝不造假（DESIGN 规则 4）。

## 每一步怎么交付

1. Claude 在叠加在上一步之上的分支里实现，过程中应用始终可用。
2. 拉取请求里附上设计预览工具（第 14 步）生成的 1440×900 前后截图、需要点一遍的交互，以及 `npm run check`
   的结果。
3. 这一步删除它所取代的旧代码和旧样式，并更新 DESIGN.md。
4. 由所有者合并。Claude 不开启自动合并。

**完成标准：** 布局、尺寸、颜色和文案与画板一致；画板上画出的每个状态都能出现；安全行为（审批、仅 Owner
可做的操作、审计、失败即关闭）不变；测试已更新；`npm run check` 通过且没有新增 Biome 错误；DESIGN.md
已更新。
